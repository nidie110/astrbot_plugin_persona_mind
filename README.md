# 人格认知引擎 · persona_mind

**1.1.2 共享判断修正版，尚未发布。** 适用版本声明见 `metadata.yaml`：AstrBot ≥ 4.11.0。

插件在主模型生成回复前调用一次模型，推断消息情境和情绪，再将情绪状态、行为、口吻、知识和语料拼入 `system_prompt`。它不主动发送消息，也不直接改写主模型的回复。引擎使用 Python 标准库；运行插件仍需 AstrBot 和可用的模型供应商。

当前决策入口是 `engine/act.py:decide()`：**八动作 × 七口吻**。`engine/intent.py` 的旧五意图保留作日志对照，不参与主行为选择。不要通过调整旧五意图来调试当前回复。

## 安装与替换

1. 停止 AstrBot，备份原插件目录、对应插件配置，以及 `data/plugin_data/astrbot_plugin_persona_mind/`。
2. 将本包的 `astrbot_plugin_persona_mind/` 替换到 `data/plugins/` 下，避免多套同名插件并存。
3. **保留原有 `data/plugin_data/astrbot_plugin_persona_mind/`**。其中包含情绪状态、人格正本、侧写与自定义语料；更新代码不需要清空这些数据。保留 `data/config/` 中的现有配置。
4. 启动 AstrBot，检查插件加载日志。先执行 `/mind selftest`，正常聊一轮后再执行 `/mind why` 核对实际注入。
5. 若需回滚，停止服务后恢复备份的代码与数据，再启动。不要在运行时覆盖状态文件。

本包没有自动安装、重启或发布步骤。仅解压不会替换运行中的插件。

## 一轮消息如何处理

1. 跳过空消息、以 `/` 开头的命令、禁用状态，以及同一用户仍在处理中的重复请求。
2. 按真实经过时间衰减情绪；读取当前用户关系和侧写。群聊不使用私聊 `recent` 原话。
3. 调用思考模型，得到情境推断、情绪标签和评价数据。情绪冲量强度为 `relevance × (0.35 + 0.65 × |desirability|)`；`control` 和 `agency` 尚未参与冲量计算。
4. 更新 core/scene 情绪，读取“情绪管理”的关系数据，计算当前关系对应的势场基线。
5. 结合消息证据、PAD、关系和可靠的上一轮机器人回复上下文，选择主行为、口吻和条数预算。
6. 检索知识，按行为、口吻和关系筛选语料，将生成要求追加到 `system_prompt`。
7. 更新侧写样本与关系、保存状态和诊断；达到配置轮数时，异步调用模型归纳侧写。主模型随后生成实际回复。

思考调用失败时降级为可用的消息证据和既有状态；注入流程异常时保留主回复通路，并记录错误。健康诊断不等于模型服务或完整消息链路的在线验收。

## 行为与表达边界

| 动作 | 含义 |
|---|---|
| `answer` | 正常应答、完成任务 |
| `care` | 关心对方 |
| `share` | 说一点自己的事 |
| `tease` | 接真实玩笑或回应针对机器人的冒犯 |
| `probe` | 追问具体信息 |
| `dodge` | 少说或不接话 |
| `coy` | 撒娇 |
| `seek` | 表达自己的低落、寻求安慰 |

七种口吻是 `plain / warm / dry / cold / playful / sharp / soft`。动作与口吻分开计算，但当前有各动作的默认口吻和资格限制，并非所有 56 种组合都会生成。

- 明确任务优先 `answer`；同时有明显低落时补充 `care`，不能以安慰替代完成任务。
- 自我否定、强烈求安慰优先关怀，不因角色“嘴硬”改成损人。
- 没有玩笑或冒犯证据，不让 `tease` 仅靠性格底分成为主行为。陌生人确实开玩笑时仍可正常接梗。
- `coy` 要有相应语言信号，并满足 `T ≥ 50、I ≥ 40`；`seek` 也要求 `I ≥ 40`。关系分档仍是 `I < 30` 生疏、`30 ≤ I < 60` 熟悉、`I ≥ 60` 亲近，行为资格与语料资格分别检查。
- 明确结束当前话题时简短收口；明确任务和强关怀需求优先，不机械地“一律闭嘴”。
- 群聊被点名时降低 `dodge`；同一会话连续不接话会触发开口限制。
- `sharp` 只在主行为为 `tease`、桥接的对他攻击性超过 30/50 时选择。
- 日常条数、每条字数是提示词约束；明确任务不套碎聊长度限制。插件不做输出截断，也不能保证主模型逐条遵守预算。

## 双层情绪与势场

每个 PAD 维度用同样规则处理。core 跨会话共享，scene 按会话保存偏移；新场景偏移为 0。

```text
core 计划冲量 = 0.40 × 本轮冲量
scene 冲量    = 1.00 × 本轮冲量
表现值        = 基线 + 0.35 × core偏移 + 0.65 × 当前scene偏移
core 半衰期   = 120 分钟
scene 半衰期  = 30 分钟
```

思考模型中的“她自己的心情”和 `pad.json` 采用独立的只读投影：`配置基线 + 0.35 × core偏移`，不带当前或上一位用户的关系基线，也不带 scene。这里保留 0.35 增益以维持原有反馈强度；对当前用户生成回复时仍使用上面的关系基线与双层混合公式。读取自身心情不会修改全局基线。

实际冲量还受重复折扣、窗口配额、单次限幅和状态边界约束。内部衰减保留浮点精度，展示时再舍入。持久化保存偏移与参照基线，切换关系基线时保留情绪残留。

“约 18% 跨场景传导”仅指：**同一孤立事件、比较事件刚发生时的增量、未命中折扣/配额/限幅、比较时没有基线变化**。此时其他场景增量为 `0.35 × 0.40 = 0.14`，本场景增量为 `0.14 + 0.65 = 0.79`，比值约 17.7%。这不是所有时刻的传导上限；scene 退得更快，之后相对比例会变化。正负情绪都能跨场景传导。

core 防刷使用 10 分钟窗口、每维每个方向累计额度 12；正向和负向分开计算。相同会话、相同事件符号在 2 分钟内重复时，core 份额逐次乘 0.5，折扣最多计 4 次。`CoreEvent.granted` 记录获准冲量用于配额，`actual` 记录真正落地变化用于诊断；饱和也会占已获准额度。这是数值防刷，不是语义上的重复内容识别。

开启势场时，`A/L/Ag/T` 分别表示好感、对他的力比多、对他的攻击性、信任。桥接的 L 和 Ag 为 0–50，先乘 2 转成 0–100；公式使用减去 50 后的中心化值：

```text
P₀  = 50 + k × (0.30a + 0.15l − 0.20ag)
Ar₀ = 40 + k × (0.25l + 0.15ag)
D₀  = 45 + k × (0.25t + 0.20ag)
```

结果夹到 0–100；`field_strength` 在公式中实际限制为 0–1。`field_enable=false` 或 `field_strength≤0` 时使用配置基线。关系基线随当前对话者改变，不能把换人造成的基线变化全归因于跨场景情绪传导。

## 管理命令与健康诊断

只注册一个 `/mind` 命令，以下均是它的子命令；仅管理员可用。

| 命令 | 用途 |
|---|---|
| `/mind` 或 `/mind status` | 当前状态、关系、知识/语料规模与健康摘要 |
| `/mind profile` | 查看当前管理员自己的档案 |
| `/mind kb [关键词]` | 查看知识与语料情况；有关键词时检索知识 |
| `/mind selftest` | 本地组件与健康检查 |
| `/mind why` | 当前会话上一轮注入的决策快照 |
| `/mind toggle` | 内存中开关；重启恢复配置值 |

`why` 使用当轮用户、关系、PAD 和桥接状态快照，并以该轮条件计算语料资格，避免把管理员当前状态混进上一位说话者的诊断。它只展示当前会话，不能用来读取其他群或私聊的快照。

`status/selftest` 显示分阶段连续失败和最近注入成功时间。注入、思考和状态读写等已接入健康统计的异常将完整堆栈写入 AstrBot 的正常插件日志，同一阶段按 60 秒限频；没有另建 `errors.log`，也不会主动给管理员发消息。先用健康摘要区分“思考失败”和“注入失败”，再看相应日志；知识加载、侧写归纳等部分路径仍单独记 warning，健康摘要不覆盖全部组件。

## 与“情绪管理”和文字人格的关系

`AffectionBridge` 按机器人账号和用户读取 `astrbot_plugin_affection` 的 `user_data.json`，缓存约 30 秒，只读不回写。读不到时使用中性回退，persona_mind 可独立运行。桥接开关 `affection_bridge` 是代码配置项，未列入这 27 项面板 schema。

这避免了两套数值相互写回，但不能保证两个插件注入的自然语言指令没有冲突，也不能保证本轮立刻看到情绪管理异步更新后的值。文字人格稿中的亲密边界、语言风格应与 traits 和情绪管理提示词核对。发生冲突时先看当轮注入和 `/mind why`，不要只调总权重。

## 数据、知识与语料

运行数据位于 `data/plugin_data/astrbot_plugin_persona_mind/`：

| 文件 | 内容 |
|---|---|
| `persona.traits.json` | 启动时读取的人格参数正本 |
| `state.json` | core/scene 状态、偏移、时间和窗口内 core 事件配额 |
| `pad.json` | 最近保存时的自身 PAD 快照，使用配置基线与加权 core 偏移，不含关系基线和 scene；离线时不会主动刷新 |
| `profiles/<uid>.json` | 关系、侧写与最近的私聊样本 |
| `kb/knowledge.md` 与其他知识文件 | 关键词命中后注入的本地知识 |
| `kb/voice.md` | 按 Markdown 二级标题分组的表达样本 |
| `mind.log` | 推断、行为、口吻和可获得的模型开销，JSONL 格式 |

语料常用分组是“关心、怼回去、说自己的日子、追问、敷衍、撒娇”。可另设“亲近、热情、闹着玩、诗与狂言”等；是否抽取取决于行为、口吻和关系资格。`answer` 不强配表达样本，空语料池也不会跨分组硬凑。语料修改后重载插件；知识文件按查询时的变更检查重载。

新档案亲密 I=20；当前正向推进只发生于长度至少 4 字的私聊，每次默认 +0.3、每天最多 +8。被识别为针对机器人的冒犯时默认 −0.6。T 当前没有自动增长机制；I 也没有按离线时间自动衰减。群聊不追加私聊原话样本。

**本地存储不等于消息不会发送给模型服务。** 思考调用接收当前消息及可用的侧写摘要，归纳调用接收侧写和 recent 样本；主模型也接收注入块。`group_light` 当前只限制最终回复的侧写注入，不阻止思考阶段使用侧写。字段白名单和敏感词正则不是完整的隐私过滤，recent 和日志仍可能包含用户内容；按实际部署的模型服务与数据要求管理这些文件。

## 验证与统计口径

在插件根目录离线运行：

```powershell
python -B -m unittest discover -s tests -v
python -B tools/evaluate.py
```

回归测试用于验证代码行为；统一评估入口是 `tools/evaluate.py`，样本来自 `tools/calibrate.py` 和 `tools/holdout.py`。四种指标必须分开报告：

| 指标 | 定义 |
|---|---|
| `strict` | 首选等于主标签 |
| `top2` | 主标签在前二中 |
| `accept` | 首选属于可接受集合 |
| `accept2` | 前二任一属于可接受集合 |

调参集未定义可接受集合，对应两列无定义，不能拿严格命中率代填。已经用于调整规则的 holdout 应称开发集，不能继续当作未见测试集。评估当前主要调用决策函数，不验证真实模型最终回复质量、完整多轮上下文或线上群聊表现。本手册不固定抄写通过数与命中率；以本次修正版的实际测试输出和交付报告为准。

## 当前限制

- 消息证据仍以词表和正则为主，反讽、引用、否定、多人指代等情况可能误判；上一轮真实回复只提供有限上下文信号。
- 行为概率是规则分数经 softmax 后的相对排序，不是经过校准的心理概率；原始分数小幅增加也可能显著改变排序。
- core 跨场景共享，不是“群间绝不串情绪”；关系势场和不同衰减速度还会改变表现值。
- 兼容旧状态格式，但旧文件若没保存参照基线或配额历史，升级无法恢复这些缺失信息。持久化最多保存最近插入的 200 个 scene；这不是按最近使用时间淘汰。
- 每轮通常增加一次模型调用，侧写归纳还可能额外调用。延迟、费用依供应商和内容而变，不承诺固定耗时或金额。
- 人物侧写按 uid 存储，尚未完整细分平台/机器人账号；多平台部署需注意相同 uid 的档案冲突。
- 本地知识是关键词检索，侧写归纳是模型推断，均可能遗漏或出错；本插件没有事实验证机制。
- 注入只提供生成要求，最终措辞仍受主模型、AstrBot 人格和其他插件影响。`budget=0` 也只是允许不回的提示，不会直接取消生成。
- 配置与 traits 中的未生效项见上文；需要调半衰期和 core/scene 权重时目前仍需修改 `Mood` 常量。

## 共享判断（1.1.2）

小鲸鱼和 QQ 侧的蓝色大肥鱼按同一 canonical identity 管理，但保留各自的场景经历。日记里的判断可以进入共享 claims，日记正文和现场经历不会自动变成 QQ 的亲身经历；QQ 侧引用外部判断时会使用“听小鲸鱼说过”的来源措辞。

每条 claim 记录 `canonical_id`、`source_scene`、`material_id`、`visibility` 和 `experience`。`visibility=private` 永远不会进入检索或 recent 注入；历史记录缺少该字段时按 shared 兼容，未知显式值按 private 处理。`material_id` 对同一素材保持稳定，更新 stance 会追加一条 JSONL 并在内存和重启加载时保留最新判断。

日记模型最多输出两条判断，由 `main.py` 写入 QQ/日记共用的 claims 库。外部小鲸鱼日记仍需手动运行 `tools/import_whale_diary.py` 导入；导入器会优先使用 BV 号作为素材 ID。`claims_recent` 默认关闭，只有显式开启才会在无话题命中时注入最近判断，以免随机打断无关对话。

## 日记（1.2.0）

她每天给自己写一篇日记，写完就是知识库里的一等公民——下次聊到相关话题会被想起来。

**素材怎么来**

- `astrbot_plugin_feiyu_video` 看完视频后写一条（标题、讲了什么、当时的反应）；
- 本插件自己把日常对话按会话节流记一条（`diary_record_chat`，默认开；同一会话两次至少隔 `diary_chat_gap` 秒，默认 900）；
- 素材落在 `data/plugin_data/astrbot_plugin_persona_mind/diary_materials/YYYY-MM-DD.jsonl`，单日最多取 40 条、单条截断 400 字进 prompt。

**什么时候写**

1. 每天到 `diary_at`（默认 `22:40`，留空=不定时）写当天；当天没有任何素材就跳过，不写空日记；
2. 启动时补一次：前几天有素材但漏写的日子会立刻补上（`diary_lookback`，默认 3 天，一次最多两篇）；
3. 每天第一次开口时再兜一次底，防止进程一直不重启却漏了几天；
4. 手动：`/mind diary`、`/mind diary 昨天`、`/mind diary 2026-10-24`。

**写完之后**

- 落到 `kb/diary/YYYY-MM-DD.md`，带 front matter（`date` / `title` / `tags` / `mood` / `source`），写完立刻重载知识库；
- 检索走 `query_diary`（只在日记里找，命中带日期）和 `mood_diary`（很低落时翻出以前开心的那天）；日记条目在打分时乘 `DIARY_PREFER=1.15`；
- 日记里形成的判断（0~2 条）写进共享 claims，正文本身不进 QQ 的“亲身经历”。

**配置**

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `diary_enable` | true | 总开关；关掉后既不写也不检索 |
| `diary_at` | `22:40` | 每天写日记的时间（HH:MM）；留空则只在有旧素材时补写 |
| `diary_record_chat` | true | 把日常对话记成素材 |
| `diary_chat_gap` | 900 | 同一会话两条聊天素材的最小间隔（秒） |
| `diary_lookback` | 3 | 往上找几天的漏写 |
| `diary_keep_days` | 30 | 素材保留天数（日记本身永久保留） |
| `diary_timeout` | 60 | 写日记的 LLM 超时（秒） |
| `diary_mood_recall` | true | 心情很低/很好时联想旧日记 |
| `diary_material_path` | 空 | 自定义素材目录 |

素材与日记都在本地插件数据目录，不上传任何外部服务。
