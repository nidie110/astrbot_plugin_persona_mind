# 人格认知引擎 · astrbot_plugin_persona_mind

> **先想再说。**
> 让她在你的 Bot 开口之前，先想一遍：你在干嘛、你真正想要什么、她此刻什么情绪、她最想说什么。
> 想到的东西不会发出去，只影响她的语气、态度和分寸。

- 插件名：`astrbot_plugin_persona_mind`
- 显示名：**人格认知引擎**
- 适用：AstrBot ≥ 4.11
- 依赖：**无**（纯标准库，不用装包、不用向量库、不用额外 API）

## 一、它解决什么问题

装之前，典型对话是这样：

```
你：不想上课
她：不想上就别硬撑
她：反正都趴地上了
```

她没做错什么——只是她在「处理信息」：识别关键词 → 归类 → 给建议。

真人不会这样。真人会先猜：**他这个点在上课、他说这句不是要建议、是想有人站他这边。**

装之后：

```
你：不想上课
她：那就趴着
她：我也不想动
她：你们教室有空调吗
```

同一个模型、同一个人格设定，差别只在于**多了一步「想」**。

这一步拆成五件事：

| 步骤 | 作用 |
|---|---|
| ① 情景推断（ToM） | 猜你在做什么、在哪、什么情绪、真正想要什么 |
| ② 情绪评价（OCC） | 这句话对她意味着什么？生气/开心/担心/心软/烦 |
| ③ 状态更新（PAD） | 更新她的情绪，并随时间衰减回基线 |
| ④ 意图计算 | 这一轮她想干嘛：安慰 / 损你 / 说自己的事 / 追问 / 敷衍 |
| ⑤ 内心注入 | 把上面拼成一段「内心」塞进 system prompt，**不发送** |

## 二、快速开始

### 方式一：插件市场（推荐）

AstrBot WebUI → 插件市场 → 搜「人格认知引擎」→ 安装。

### 方式二：GitHub 链接安装

WebUI → 插件市场 → 「从链接安装」→ 填仓库地址。

### 方式三：手动

把整个 `astrbot_plugin_persona_mind/` 目录放进：

```
AstrBot/data/plugins/astrbot_plugin_persona_mind/
```

然后重启 AstrBot。

### 首次配置（3 步）

**第 1 步：填一个「内心」用的模型**

WebUI → 插件配置 → 人格认知引擎 → `think_provider`

建议填一个**便宜、快**的模型，例如：

```
deepseek/deepseek-flash
```

留空 = 用当前会话的默认模型（也能跑，但会贵一点、慢一点）。

**第 2 步：自检**

在聊天里发：

```
/mind selftest
```

看到 5 个 ✓ 就成功了：

```
✓ 配置 —
✓ 知识库 — 1 段
✓ 语料库 — 12 句
✓ 侧写目录 — data/plugin_data/astrbot_plugin_persona_mind/profiles
✓ 状态文件 — data/plugin_data/astrbot_plugin_persona_mind/state.json
```

**第 3 步：看它有没有在工作**

随便聊两句，然后发：

```
/mind
```

会显示她此刻的情绪值、和你的关系值、知识/语料规模。

## 三、每轮到底发生了什么

```
你发一条消息
   │
   ├─ ① 调一次小模型（think_provider）做「内心活动」
   │     输入：当前时间 + 你的消息 + 最近两句 + 你对她的印象摘要
   │     输出：{他在做什么, 在哪, 情绪, 真正想要, OCC四问, 情绪标签, 你的情绪值}
   │     耗时：约 1~2 秒
   │
   ├─ ② 按情绪标签更新她的 PAD（并先做一次时间衰减）
   │
   ├─ ③ 算五个意图（安慰/损/自述/追问/敷衍），套硬规则
   │
   ├─ ④ 检索知识库（命中才注入，最多 3 段）
   │     按当前意图抽 1~3 句语料（只当味道样本）
   │
   ├─ ⑤ 拼成一段「内心」→ 追加到 system prompt（不发送）
   │
   └─ ⑥ 主模型正常生成回复
```

**关键点**：第 ①～⑤ 步的产物用户永远看不到，它只改变主模型的输入。

**如果第 ① 步失败**（超时/报错）：跳过注入，主模型照常回复。**不会因为她「想不出来」就不说话。**

## 四、配置项全表

### 基础

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关。关掉等于没装 |
| `think_provider` | 空 | 「内心活动」用哪个模型。留空用会话默认 |
| `think_timeout` | `15` | 单次思考超时（秒）。超时自动降级 |
| `group_light` | `true` | 群聊轻量模式：不注入侧写，语料只取 1 句 |
| `max_inject_chars` | `1200` | 注入内容字数上限 |
| `log_enable` | `true` | 记录每轮推断到 `mind.log`（调试用，平时可关） |

### 记忆与知识

| 配置项 | 默认 | 说明 |
|---|---|---|
| `profile_enable` | `true` | 启用人物侧写（慢慢认识每个人） |
| `summarize_every` | `20` | 每多少轮归纳一次侧写；`0` = 关闭自动归纳 |
| `kb_enable` | `true` | 启用本地知识库检索 |
| `voice_enable` | `true` | 启用语料库（按意图抽句） |
| `extra_kb_files` | `[]` | 额外知识文件（绝对路径），改完自动重载 |

### 情绪

| 配置项 | 默认 | 说明 |
|---|---|---|
| `decay_minutes` | `5.0` | 情绪衰减步长（分钟） |
| `decay_ratio` | `0.2` | 每次向基线回归多少（0.2 = 20%） |
| `affect_p` | `60` | 情绪基线·愉悦 |
| `affect_ar` | `45` | 情绪基线·唤醒（越低越容易敷衍） |
| `affect_d` | `50` | 情绪基线·支配（底气） |

### 人格（大五）

| 配置项 | 默认 | 说明 | 调高的效果 |
|---|---|---|---|
| `persona_o` | `75` | 开放性 | 更爱追问、爱玩梗 |
| `persona_c` | `35` | 尽责性 | 更靠谱、少摸鱼 |
| `persona_e` | `55` | 外向性 | 话更多、更主动说自己的事 |
| `persona_a` | `40` | 宜人性 | **更温和、少怼人**（调低则更嘴硬） |
| `persona_n` | `60` | 神经质 | 情绪波动更大、更容易被戳到 |

### 关系

| 配置项 | 默认 | 说明 |
|---|---|---|
| `rel_t` | `55` | 新对话者的初始信任 |
| `rel_i` | `40` | 新对话者的初始亲密 |

## 六、自定义你的角色

引擎是通用的，你要给它三样东西：**人格数字、语料、知识**。

### 1. 人格：五个数字怎么定

不用精确，先按直觉填，再微调。参考：

| 你想要的角色 | O | C | E | A | N |
|---|---|---|---|---|---|
| 傲娇嘴硬 | 70 | 40 | 55 | **30** | 60 |
| 温柔姐姐 | 60 | 70 | 60 | **85** | 30 |
| 高冷毒舌 | 80 | 70 | 30 | **20** | 40 |
| 活泼小狗 | 85 | 30 | **90** | 75 | 50 |
| 阴郁文艺 | 90 | 40 | 25 | 50 | **80** |

**宜人性 A 是最敏感的一个**：它直接决定"怼不怼人"。
A 低到 30 以下，她会逢话都顶；A 到 70 以上，她会变得很配合、几乎不损人。

### 2. 语料：`kb/voice.md`

**这是提升"人味"性价比最高的一步**，比写两千字人设有效。

格式：

```md
## 关心
你没事吧？
累了就歇着，别硬撑

## 怼回去
哈？就这？
你很嚣张嘛

## 说自己的日子
今天有点忙，刚歇下来
诶 我跟你说个事

## 追问
然后呢
说清楚点

## 敷衍
嗯
就这样？

## 亲近
你刚才那句，很好听
```

规则：

- 每个 `##` 是一个分组名，引擎按当前意图自动抽
- **必须有这五个分组**：`关心`、`怼回去`、`说自己的日子`、`追问`、`敷衍`
- 分组名固定，顺序随意；可以额外加 `亲近`、`闹着玩`、`兴奋`、`撒娇`（作为"味道补充"随机混入）
- 每句一行，**写她真的会说的话**，别写"她应该说"的话
- 建议每组 5~10 句，总数 40~80 句最有效

> 引擎会明确告诉模型：「借味道，别照抄」。所以不用担心它复读。

### 3. 知识：`kb/*.md`

把"她应该知道的东西"写成 markdown 放进去：术语、梗、圈内黑话、人物关系、设定。

```md
# 足球黑话

## 术语
- 越位：进攻球员在传球瞬间比倒数第二名防守球员更靠近球门线。
- 摆大巴：全队退到禁区前防守。

## 梗
- 「赛后情书」：球迷赛后写长文，形式像情书。
```

规则：

- 按 `##` 标题切块，每块 20~350 字效果最好
- **话题命中才注入**，最多 3 段，所以不怕写多
- 别写时效性事实（"现任主教练是谁"），写错她会自信地说错话
- 建议在文件末尾写一条边界：

```md
## 边界
- 不懂就说不太懂，别硬编。
```

### 4. 外部知识文件

如果知识在别处（日记、笔记、另一个插件产出），配置 `extra_kb_files`：

```json
["C:\\Users\\你\\notes\\diary.md", "/home/user/notes.md"]
```

文件更新后**下一次查询自动重载**，不用重启。

## 七、人物侧写

每个对话者一份 JSON，存在 `profiles/<uid>.json`。

### 字段

| 字段 | 含义 | 怎么来 |
|---|---|---|
| `称呼` | 她怎么叫这个人 | 归纳 / 手动 |
| `身份` | 学生 / 上班族 / 不知道 | 归纳 |
| `作息` | 下午有课、常熬夜 | 归纳 |
| `在做什么` | 最近在忙什么 | 归纳 |
| `兴趣` | 足球、动漫、猫 | 归纳 |
| `雷点` | 别提的话题 | 归纳 |
| `说话习惯` | 句长、标点、表情包频率 | 归纳 |
| `近况` | 带时间的近期事件 | 每轮追加 |
| `note` | **没把握的猜测**（不参与生成） | 归纳 |
| `T` / `I` | 信任 / 亲密 | 自动累积 |
| `recent` | 最近 20 条原话（供归纳用） | 自动 |

### 手动修改

直接编辑 JSON 就行，改完下一轮生效。

```json
{
  "uid": "12345",
  "称呼": "球迷",
  "身份": "学生",
  "兴趣": ["曼联", "足球"],
  "雷点": ["被叫大肥鱼"],
  "T": 62,
  "I": 55
}
```

### 清空

删掉对应 JSON 文件即可，她会重新认识这个人。

### 为什么把 `note` 单独放

因为**猜错一次比不猜更伤人**。`note` 里的内容不参与生成，只作为观察记录，等归纳时再决定要不要升级成事实。

## 八、调参实战

### 症状 1：太黏人、太顺着你

| 改什么 | 怎么改 |
|---|---|
| `persona_a` | 调**低**（40 → 30），更有脾气 |
| `persona_n` | 调低一点，情绪波动小一些 |

### 症状 2：太冷、爱答不理

| 改什么 | 怎么改 |
|---|---|
| `affect_ar` | 调**高**（45 → 60），别总犯困 |
| `persona_a` | 调**高**（40 → 55），少怼人 |
| `persona_e` | 调高（55 → 70），更主动 |

### 症状 3：群里太吵

| 改什么 | 怎么改 |
|---|---|
| `group_light` | 保持 `true` |
| `extra_kb_files` | 群聊不挂额外的知识文件 |
| 改代码 | `engine/intent.py` 里 `dodge` 的群聊系数 `0.15` 调到 `0.25` |

### 症状 4：情绪一会儿就忘

| 改什么 | 怎么改 |
|---|---|
| `decay_minutes` | 调**大**（5 → 15），情绪留得久 |
| `decay_ratio` | 调**小**（0.2 → 0.1），衰减更慢 |

### 症状 5：记错人 / 编造事实

| 改什么 | 怎么改 |
|---|---|
| `summarize_every` | 调**大**（20 → 40），归纳更保守 |
| 手动 | 直接编辑 `profiles/*.json` 改掉错的字段 |
| 人格里加 | 「不确定的事就说不知道」 |

### 症状 6：知识库不命中

| 原因 | 解决 |
|---|---|
| 词太泛（"推荐""好看"） | 改成具体名词（"曼联""越位"） |
| 段落太长 | 按 `##` 切开，每块 350 字以内 |
| 单字词 | 引擎用字二元组，对单字不敏感，换成双字词 |

## 九、常见问题

**Q：装了没反应？**
A：检查 ①`enable` 是否为 true ②`think_provider` 填的模型是否存在 ③`/mind selftest` ④看 `mind.log` 有没有新记录。

**Q：变慢了？**
A：每轮多一次模型调用，实测 +1~2 秒。想更快就换更小的模型，或调小 `think_timeout`（超时会自动跳过）。

**Q：token 花得多吗？**
A：每轮多约 500~900 token。按 flash 级模型算，一天几百轮也就几毛钱。

**Q：和记忆插件（iris 等）冲突吗？**
A：不冲突。记忆插件管"长期记住什么"，这个插件管"这一轮怎么想"。

**Q：和别的人格增强插件能一起用吗？**
A：能，但可能出现两份人格指令打架。建议只留一个负责"语气"的。

**Q：为什么她还是会说客服腔？**
A：这个引擎负责"想"，不负责"改写"。客服腔主要来自 ①人格里没写反例 ②语料库没内容。先补 `voice.md`。

**Q：能用在群聊吗？**
A：能。群聊默认走轻量模式（不注入侧写），避免过度解读。

**Q：能只对私聊生效吗？**
A：可以，但需要改一行代码：在 `main.py` 的 `_inject` 开头加 `if scene == "group": return`。

**Q：数据在哪？**
A：`AstrBot/data/plugin_data/astrbot_plugin_persona_mind/`，删掉这个目录等于重置。

**Q：升级会丢数据吗？**
A：不会。插件代码和 `data/plugin_data/` 是分离的。

## 十、设计与理论

### 1. 十个数字

| 层 | 数字 | 变化速度 |
|---|---|---|
| 人格（大五） | O / C / E / A / N | 周级，基本不动 |
| 情绪（PAD） | P / Ar / D | 分钟级，会衰减 |
| 关系 | T / I | 天级，只累积不衰减 |

### 2. OCC 四问 → 情绪

Ortony, Clore & Collins (1988) 认为情绪来自**评价**，四个维度：

| 问题 | 取值 |
|---|---|
| 目标相关性 | 0~1 |
| 目标一致性 | −1~1 |
| 责任归属 | 对方 / 我 / 无 |
| 可控性 | 0~1 |

映射表（可在 `engine/appraisal.py` 改）：

| 组合 | 情绪 | ΔP | ΔAr | ΔD |
|---|---|---|---|---|
| 高相关 + 不利 + 对方 + 低可控 | 生气 | −10 | +15 | +5 |
| 高相关 + 有利 + 对方 | 开心 | +12 | +8 | 0 |
| 高相关 + 不利 + 我 + 高可控 | 自责 | −8 | +10 | −10 |
| 高相关 + 不确定 | 担心 | −5 | +8 | −5 |
| 对方示弱 | 心软 | +3 | −5 | −3 |

### 3. ToM 四字段

Theory of Mind（Premack & Woodruff, 1978）：推断他人心理状态的能力。
工程上落成四个待填字段，允许猜错——猜错能变成话题。

### 4. 五意图

| 意图 | 主导证据 |
|---|---|
| 安慰 care | 对方情绪低 / 求助词 / 亲密高 |
| 损他 tease | 玩闹词 / 心情好 / 宜人性低 |
| 自述 share | 被问"你呢" / 心情好 / 外向 |
| 追问 probe | 有信息缺口（提问）/ 开放 / 外向 |
| 敷衍 dodge | 唤醒低 / 不熟 / 群里 |

**打分方式：证据驱动 + 低温度 softmax（τ=0.12）。**

> 为什么不用加权平均：第一版就是加权平均，五个分数全挤在 0.5 附近，排序几乎不变——
> 永远在同一两个意图里打转。这个坑写在代码注释里。

**硬规则优先级高于公式**：

- 出现雷点词 → 损 0.8、安慰 0.1
- 对方明确求助 → 安慰 0.8、损 0.2
- 对方情绪 < 40 → 追问 ×0.7（别审问一个难过的人）
- 对方需要安慰 → 敷衍 ×(1−0.6×需求)（心软时不躲）

### 5. 学术出处

| 主题 | 出处 |
|---|---|
| PAD 情绪模型 | Mehrabian & Russell, *An Approach to Environmental Psychology* (1974) |
| OCC 认知评价 | Ortony, Clore & Collins, *The Cognitive Structure of Emotions* (1988) |
| 评价理论综述 | Scherer, *Appraisal Processes in Emotion* (2001) |
| 心理理论 ToM | Premack & Woodruff (1978) |
| 礼貌与面子 | Brown & Levinson, *Politeness* (1987) |
| 社会渗透 | Altman & Taylor, *Social Penetration* (1973) |
| 虚拟角色情绪架构 | Gebhard, *ALMA: A Layered Model of Affect* (2005) |
| 大五人格 | Costa & McCrae, NEO-PI-R (1992) |

**没有照搬整套学术架构**（ALMA / FAtiMA 那类）：维护成本高，出问题分不清是哪层错。
这里只取"评价 → 情绪 → 表达"这一条主干，每层单独可观测。

## 十一、数据与文件

```
AstrBot/data/plugin_data/astrbot_plugin_persona_mind/
├── state.json           # 她的 PAD 情绪（含时间戳）
├── profiles/            # 每人一份侧写
│   └── <uid>.json
├── kb/
│   ├── voice.md         # 语料库（首次启动自动生成模板）
│   └── knowledge.md     # 知识库（同上）
└── mind.log             # 每轮推断记录（JSONL，可删）
```

`mind.log` 一行示例：

```json
{"t":"10-22 19:41","uid":"3388708615","scene":"private","emotion":"Tender",
 "affect":{"P":63,"Ar":40,"D":47},"thought":{"doing":"在教室","want":"被认同"},
 "intent":{"care":0.44,"tease":0.35},"budget":3,"kb":1}
```

**这份日志是排障的关键**：她答得不对时，一眼能看出是情景猜错、情绪错、还是意图选错。

## 十二、性能与成本

| 项 | 数值 |
|---|---|
| 每轮额外调用 | 1 次（think_provider） |
| 额外延迟 | 1~2 秒 |
| 额外 token | 500~900 / 轮 |
| 侧写归纳 | 每 20 轮 1 次 |
| 知识检索 | 本地计算，< 5ms |
| 失败降级 | 思考超时 → 跳过注入，正常回复 |

---

## 十三、隐私与安全

- 侧写**只记录**偏好、近况、称呼、兴趣、雷点
- **不记录**手机号、住址、证件、支付信息（正则拦截，命中直接丢弃）
- 所有数据**本地存储**，不发送给第三方
- 引擎**从不主动发消息**，只影响生成
- `mind.log` 可随时删除

---

## 十四、已知限制

1. **ToM 会猜错**，而且不会自我纠正。可以在人格里加一句"猜错了顺着改"。
2. **每轮多一次调用**，省钱可以只在私聊/@ 时启用。
3. **知识库是关键词级检索**（字二元组 + IDF），不是语义检索。语料过万字后建议换 embedding。
4. **侧写归纳依赖模型**，偶尔会写出奇怪字段；白名单和长度限制能挡住大部分。
5. **不做长期记忆**——那是记忆插件的事。这里只管"这一轮怎么想"。
6. **不负责改写**。它不拦客服腔，只负责让模型"先想"，具体措辞靠人格和语料。

## 十五、开发与扩展

### 跑测试

引擎不依赖 AstrBot，可单独测：

```bash
cd astrbot_plugin_persona_mind
python -m unittest discover -s tests -v
```

### 目录

```
├── main.py              # 插件入口：钩子、指令、持久化
├── engine/
│   ├── affect.py        # PAD + 衰减
│   ├── appraisal.py     # OCC + ToM 提示词
│   ├── intent.py        # 五意图 + softmax + 硬规则
│   ├── profiles.py      # 侧写 + 隐私过滤
│   ├── knowledge.py     # 本地知识库
│   ├── voice.py         # 语料库
│   └── prompts.py       # 注入拼装
├── _conf_schema.json    # 配置 schema
├── metadata.yaml        # 市场元数据
└── tests/
```

### 扩展点

| 想改什么 | 改哪里 |
|---|---|
| 情绪映射强度 | `engine/appraisal.py` 的 `OCC_EFFECTS` |
| 意图权重/温度 | `engine/intent.py` 的 `scores()` |
| 硬规则 | `engine/intent.py` 的 `apply_overrides()` |
| 注入格式 | `engine/prompts.py` 的 `render()` |
| 检索算法 | `engine/knowledge.py` 的 `query()`（换向量检索时保持接口） |
| 说话条数 | `engine/intent.py` 的 `line_budget()` |

### 想加向量检索

`KnowledgeBase.query()` 保持签名不变，内部换成 embedding 即可。
发布版故意不默认要求 embedding，因为很多人卡在配这一步。
