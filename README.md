# 人格认知引擎 · persona_mind

**给 AstrBot 里的 bot 一份"当下的人格"——不是一串写死的静态人设，而是一套会随时间衰减、被对话改变、并且记得住的心情、关系与判断。**

`版本 1.2.1` · `AstrBot ≥ 4.11.0` · `MIT` · `零第三方依赖（仅 Python 标准库）`

---

## 这是什么

大多数人设插件的做法是：把人物小传写进系统提示词，每轮都原样贴一遍。结果就是——不管昨天刚吵过架、还是今天刚被夸了一句，她永远是同一副面孔、同一个语气。

`persona_mind` 换了个思路：**在主模型开口之前，先替她想一遍。**

每一轮对话，它会：

1. **判断这句话对她意味着什么**（是任务？是玩笑？是冒犯？是在求安慰？）
2. **更新她此刻的情绪**（愉悦/唤醒/支配三维，会自然回落到基线）
3. **更新她和这个人的关系**（信任、亲密度，慢慢积累或消耗）
4. **决定现在怎么回**（八种动作 × 七种口吻，先选"做什么"，再选"怎么说"）
5. **翻出该想起来的东西**（本地知识、以前的日记、她平时怎么说话）
6. 最后把以上结论压成一段注入，交给主模型生成实际回复

所以她会有"当天的人格"：睡醒时话少，被戳到会变冷，熟人之间才撒娇，吵完架之后语气会留一点余味。

**它不做什么**

- 不主动发消息（主动开口交给 `astrbot_plugin_proactive_chat` 之类的插件）
- 不改写主模型的回复，只提供生成要求
- 不接管 AstrBot 的人格稿，两者是叠加关系
- 思考模型调用失败时降级为规则决策，**主回复通路不受影响**

## 能做什么

### 情绪：双层 PAD，会衰减也会残留

情绪分两层存放：`core`（跨会话共享，半衰期 120 分钟）和 `scene`（按会话独立，半衰期 30 分钟）。当前说话的人换一个，基线跟着换，但情绪余温还在。

表现值 = 基线 + 0.35 × core 偏移 + 0.65 × scene 偏移。所以同一件事，刚发生时的反应强烈，过一会儿就淡了，但不会瞬间归零。

### 动作：八动作 × 七口吻

| 动作 | 含义 |
|---|---|
| `answer` | 正常应答、完成任务 |
| `care` | 关心对方 |
| `share` | 说一点自己的事 |
| `tease` | 接真实玩笑，或回应针对机器人的冒犯 |
| `probe` | 追问具体信息 |
| `dodge` | 少说或不接话 |
| `coy` | 撒娇 |
| `seek` | 表达自己的低落，寻求安慰 |

七种口吻：`plain / warm / dry / cold / playful / sharp / soft`。

动作和口吻分开算，带资格限制——撒娇要关系够近、还要有相应的语言信号；`sharp` 只在真的在怼人时才出现。**不是所有 56 种组合都能生成**，这是刻意的。

### 关系：会变的基线

关系由可信度、亲密度等维度组成，**决定她情绪的"落脚点"**：对陌生人再客气，基线也是生疏的；对熟人发脾气之后，回落的位置也更高。

开启"势场"后，关系还会反过来影响当前情绪的表现强度——越亲近的人，影响越明显。

**可信度 T 是会动的**（1.2.2 起）：记的是「这段时间你怎么对她」，不是「她多喜欢你」。三条规则，全部有当日上限，防止一次聊爽就拉满：

| 事件 | 变化 | 附加条件 |
|---|---|---|
| 隔天还来找她 | +`rel_trust_day_gain`（默认 0.4） | 只有私聊算，群聊只滚动日期 |
| 愿意讲自己的事 | +`rel_trust_share_gain`（默认 0.1） | 有实词才算；「嗯」「哈哈」「🙂」不算 |
| 骂她 | −`rel_trust_penalty`（默认 0.8） | 记净额，连骂也不会把额度刷成负收益 |

当天净变动不超过 `rel_trust_cap_day`（默认 1.5，涨跌共用：一天最多净涨 1.5，也最多净跌 1.5）。隔三天没来再出现，也只补一次"返场"分，不会把缺席的天数补回来。

> 日期按**宿主时区**算（`time.strftime("%Y-%m-%d")`）。Docker 里容器常是 UTC，和北京时间差 8 小时：容器里的一天从北京时间 08:00 才开始，"当日额度"和"隔天返场"都会跟着错位。部署在容器里的话，请给容器设 `TZ=Asia/Shanghai`。

### 骂她，还是在逗她

同一句「你个笨蛋」，在朋友嘴里是笑，在陌生人嘴里是刺。所以她先判**这条话是冲着她来的攻击，还是闹着玩**，再决定要不要记这一笔：

- **先看玩笑信号**：`哈哈哈`、`笑死`、`狗头`、`逗你`、`笨蛋`、`小胖` 这类词，句尾的 `啦/呀/嘛/~`，以及「你是不是傻」这种反问式损
- **剩下还硬的才算骂**：`闭嘴`、`滚`、`垃圾`、`傻逼`、`我讨厌你`，而且要求这话确实指向她——「这电影真垃圾」不会扣她的分
- **她自己也有判断权**：每轮的心智推断会额外回答一次「这是骂还是玩笑」，模型给出答案就以它为准，规则只做兜底；模型没给或写脏了，才回落到词表

判成玩笑时她照样会损回去（口吻变 playful），但**不动可信度**；只有真骂才记账。宁可把真骂误判成玩笑——那只是少扣一次分，反过来会让人凭白背一笔账。

### 小鲸鱼的日记也会进她的库（1.3.1）

桌面端那个「小鲸鱼」（dsh-world）每晚写一篇日记。插件会按内容哈希把 `~/.dsh/worlds/default/diary/*.md`
增量同步进知识库「小鲸鱼日记」（文档名带 `小鲸鱼-` 前缀，不会跟自己的日记撞名）。

聊到相关话题时，她最多想起一条，而且必须说清来源：

> 小鲸鱼（住在桌面端的那个你）写下的东西——她不是你，那不是你的经历

也就是说，她可以说「小鲸鱼说过」，不能说「我刚看过」。有 45 分钟冷却、词面闸门（同一 BV 或至少两个词重合），
对不上就当没看见；库或目录读不到就静默跳过，绝不拖慢回复。

配置：`whale_enable`、`whale_dir`、`whale_kb`、`whale_sync_minutes`（默认 30 分钟增量检查一次）、
`whale_cooldown_minutes`（默认 45 分钟才允许再提一次）。

### 一次说几句，就发几个气泡（1.3.2）

她按人格会一次说 2~3 句，但模型经常把它们写成一行，QQ 那头就变成一整块文字。插件在发送前会按句末标点替她拆开：

```text
在呢。 // 刚看完一个视频，讲的是鲸鱼在深海唱歌，听得我有点走神。 // 你呢？
```

- 只有整段没有句号、且超过 30 字时，才退到逗号切；「趴着，听风扇」不会被切碎。
- 代码块、链接、短于 `split_min_chars`（默认 8）的回复不拆。
- 还需要 AstrBot 打开「分段回复」：`platform_settings.segmented_reply.enable = true`（`split_mode=regex`、`regex="[^\n]+"`），否则多个气泡会被合并成一次发送。

### 记得住人：人物侧写

每轮积累样本，每 20 轮（可配）自动归纳一次侧写：这个人关心什么、说话什么风格、和他相处要注意什么。下次开口时这些认知会参与决策。

### 记得住事：知识与语料

- **知识库**：默认挂 AstrBot 自带的知识库（向量检索）；没配也可以切回本地 Markdown 的关键词检索——`kb_backend` 一个开关的事
- **语料库**：按二级标题分组（关心 / 怼回去 / 说自己的日子 / 追问 / 敷衍 / 撒娇 …），按当前动作和关系抽一两句"她平时怎么说"，让语气保持一致

### 日记：每天 22:40 自己写一篇

她会把自己一天的素材写成日记，落进知识库——**下次聊到相关的事，这篇日记会被想起来**。

素材从哪来：

- 看过的视频（`astrbot_plugin_feiyu_video` 看完写一条）
- 自己的探索（`astrbot_plugin_feiyu_explore` 定时看视频/翻文章）
- 当天聊过的话（按会话节流，同一会话 15 分钟内只记一条）

日记带 `title / tags / mood / source`，低落的夜晚会去翻以前开心那天的日记。**当天没有素材就跳过，不写空话。**

### 共享判断：一种"她确实说过"

同一个角色在多个场景出现时（比如 QQ 群和另一个私聊 bot），对同一件事的判断可以共享，但**经历不共享**——日记里的判断能被引用，正文不会变成"她的亲身经历"。引用时会带来源措辞（"听小鲸鱼说过"）。

### 演化的信念（可选）

`evolution_mode` 打开后，反复出现的判断会被沉淀成长期信念（默认 `rule` 档，当场结算；`daily` 档每天归纳一次），带确认次数、分位阈值与历史保留策略。默认档位保守，不影响正常对话。

### 只读桥接"情绪管理"

装了 `astrbot_plugin_affection` 的话，可以只读取它的情绪数值作为参考（缓存 30 秒，**只读不写回**），避免两套数值互相打架。没装也能独立运行。

## 她大体怎么跑

一轮消息的处理流程：

```text
用户发来一句话
   │
   ├─ 过滤：空消息 / 以 / 开头的命令 / 已禁用 / 同用户重复请求（跳过）
   │
   ├─ 按真实经过时间衰减情绪，读取当前对话者关系与侧写
   │
   ├─ 调用「思考模型」（一次额外调用，不是主模型）
   │     ├─ 情境推断：这是任务、玩笑、冒犯、求安慰，还是闲聊？
   │     ├─ 情绪标签与强度：这句话让她开心/难过/烦到什么程度
   │     └─ 评价数据：这件事对她有多相关、多重要
   │
   ├─ 更新双层情绪（core / scene），按关系算出势场基线
   │
   ├─ act.decide()：选主行为 + 口吻 + 条数预算（八动作 × 七口吻，带资格判定）
   │
   ├─ 检索：本地知识（关键词）+ 相关日记 + 语料抽样
   │
   ├─ 拼装：把「现在什么心情 / 怎么回 / 记得什么 / 平时怎么说」写成一段注入
   │
   ├─ 主模型生成回复 ← 真正的回复仍然由主模型写
   │
   └─ 收尾：更新侧写样本与关系、落盘状态、写诊断日志
```

关键点：

- **每个环节都能降级**：思考模型超时 → 用规则决策；注入异常 → 保留主回复；状态读写失败 → 记日志继续
- **注入有字数上限**（默认 1200 字），防止把主模型的上下文挤爆
- **群聊轻量模式**（默认开）：群里不注入侧写摘要、语料最多一句，避免对着陌生人过度解读

对应的代码位置：

| 环节 | 文件 |
|---|---|
| 事件接线、供应商解析、管理命令、状态与诊断 | `main.py` |
| 八动作、七口吻、资格与预算 | `engine/act.py` |
| 双层 PAD、势场、衰减、配额 | `engine/affect.py` |
| 思考提示词、解析、注入拼装 | `engine/appraisal.py`、`engine/prompts.py` |
| 关系与侧写 | `engine/profiles.py` |
| 知识检索、语料抽样 | `engine/knowledge.py`、`engine/voice.py` |
| 日记子系统 | `engine/diary.py` |
| 共享判断 | `engine/claims.py` |
| 信念演化 | `engine/self_model.py` |
| 只读桥接 | `engine/bridge.py` |

## 快速开始

1. 安装 **AstrBot ≥ 4.11.0**，能正常对话
2. 把 `astrbot_plugin_persona_mind/` 放进 `data/plugins/`
3. 重启 AstrBot，确认日志里出现插件加载
4. 发 **`/mind selftest`** 自检
5. 正常聊两轮后发 **`/mind why`**，看它到底往 prompt 里塞了什么

**首次配置建议**（其余保持默认即可）：

| 场景 | 怎么改 |
|---|---|
| 不知道选哪个模型做"思考" | `think_provider` 留空，会自动优先选 DeepSeek 系 |
| 觉得太贵/太慢 | `think_timeout` 调小到 8，或关掉 `log_enable` |
| 她太安静 / 太话痨 | 调 `persona_e`（外向性）和 `chars_per_line` |
| 她太凶 / 太好说话 | 调 `persona_a`（宜人性，越低越嘴硬） |
| 情绪太飘 / 太木 | 调 `persona_n`（神经质）与 `affect_p` 基线 |

人格参数的**正本**在 `data/plugin_data/astrbot_plugin_persona_mind/persona.traits.json`：文件存在时以文件为准，面板改不动它——这是为了避免两处配置互相覆盖。

## 知识库后端（1.3.0）

两种后端，配置里 `kb_backend` 切：

| 值 | 用的是什么 | 什么时候选 |
|---|---|---|
| `astrbot`（默认） | AstrBot 自带知识库（FAISS 向量 + BM25 融合） | 你已经建好库、想要更好的召回 |
| `local` | 插件自带的字二元组 + IDF 检索（零依赖） | 没配向量服务，或者想完全离线 |

自带后端要三样东西：①一个 Embedding Provider（本机用 `D:\qqaibot	oolseiyu_embed_server.py` 起的本地 768 维服务，地址 `http://127.0.0.1:8765/v1`）②两个库 `大肥鱼常识`、`大肥鱼日记` ③`kb_name_knowledge` / `kb_name_diary` 填对名字。

**失败会退**：自带库整个不可用（服务没起、维度不匹配、库被删）时，检索直接退回本地 `kb/*.md`，只记一条 warning，不影响回复。

**偏好没有丢**：自带库的 chunk 只有三个元数据、没有 tags，所以标签命中加分与日记 ×1.15 在重排时补回来（标签和日期仍从本地 frontmatter 读）。此外自带库「必返回非空」，所以注入前先用本地检索当闸门——本地一条都命中不了，这轮就不注入。

## 让她自然地用这些本事（人格设定里要写什么）

### 一句话结论

**人格设定里只写「什么时候该动手」，不要写工具名、参数名和调用格式。**
参数格式由插件在**真要动手的那一轮**临时告诉她 —— 这部分是 `engine/specs.py` + `engine/selector.py` 干的活。

### 为什么这么分工

她每轮看得到的指令分成三层，寿命完全不同：

| 层 | 内容 | 每轮都用得上吗 | 放哪 |
|---|---|---|---|
| **判断**（Policy） | 什么时候算「他在让我做事」、没有对应动作时怎么说、失败时说人话 | 用得上，每一轮都在判 | 人格设定里（常驻） |
| **能力**（Capability） | 她手上有什么本事 | 用得上（她得知道自己会什么） | 插件每轮拼（`_feiyu_caps.json`） |
| **格式**（Format） | 13 个动作各自的参数怎么填 | **用不上**：这一轮最多用其中一个 | 插件按需注入（命中才发） |

三个人一起算出来的一笔账（每轮字数）：

| | 改之前（1.3.5） | 改之后（1.3.6） |
|---|---|---|
| 人格里的格式段 | 1365 字，41 行 | 651 字，只写触发线 |
| 每轮拼进自述的格式 | 547（普通）/ 761（管理员），**全量常发** | 0（没命中）～ 约 230（命中两个动作） |
| 超预算时怎么办 | 按字符硬切到 1300，切点落在半行上 | 按整块丢并记日志，绝不切半行 |
| 实际每轮总量 | 1523 / 1806（且尾部被切掉） | **982**（没命中）/ **1139**（命中一个）/ **1201**（命中两个）；妈妈纸条有货时再加约 200 |

**被切掉的那部分是真实损失**：管理员会话实测 1806 字，超出 1300 的部分是「格式尾注 + 整段妈妈纸条」，而妈妈纸条 7 天只有一个、丢一次就是丢一天。

**更危险的是漂移**：格式和「什么时候用」写在两份文件里之后就开始对不上。1.3.5 的人格/规范里给「发说说」写过 `visibility="<private|friends|public>"`，而 `feiyu` 的签名里只有 `action / target / text / question` —— 管理员照着那句发，AstrBot 直接 `TypeError`。这种错跑得通、日志全绿、只有真去发的时候才炸。现在格式统一收进 `engine/specs.py`，启动自检会拿它和工具签名逐字比对，对不上就打 `[mind] 动作没接上：…`。

### 装什么才有入口

`feiyu` 这个工具是**本插件提供的唯一任务级入口**，其余 `feiyu_*` 插件在 `__init__` 里把自己的动作注册进同一张表。

```
astrbot_plugin_persona_mind   ← 提供 feiyu(action, target, text, question)，负责分派
   ├── feiyu_video    注册：看视频、认人
   ├── feiyu_browse   注册：搜、读网页、截图（另给管理员一个 page_do 调试口）
   ├── feiyu_comment  注册：发评论（管理员）、读评论（所有人）
   ├── feiyu_draw     注册：画
   ├── feiyu_voice    注册：说
   ├── feiyu_mom      注册：问妈妈
   └── feiyu_qzone    注册：改昵称、改签名、改性别、发说说
```

**所以：必须装 `persona_mind`。** 只装 `feiyu_browse` 而不装 `persona_mind` 时，模型那边一个动作都看不到 —— 不是坏了，是没有入口。

动作注册不上时（插件被禁用、依赖缺失），`feiyu` 的说明和人格里的清单都不该再承诺它。启动 20 秒后自检会打一行：

```
[mind] 动作自检通过（13 个动作，0 漂移，可用 13 个）
[mind] 动作没接上：改签名：注册表里没有（多半是对应插件被禁用了，不影响其它动作）
```

### 你要做的两步

1. **把下面那一段贴进人格设定**（AstrBot WebUI → 人格 → 你的那张卡 → 系统提示词末尾）。也可以直接跑脚本。
2. **别再往人格里写工具名和参数**。写了会变成「同一件事两处说法」，而且人格不会随插件启停更新 —— 插件禁用了，人格还在承诺，她就会照着一条走不通的路去调。

### 可以直接复制的一段（1.3.6，逐字）

前后两个 `##` 标记是给脚本做幂等替换用的，手工贴也建议带上。

```text
## 你会用的东西（什么时候动手）

听到一句话，先问自己三件事：这是让我做一件具体的事吗？我手上有没有对应的动作？没有就直说「这个我做不了」，再说我能做的那部分。
能做的，就在这一轮做完再开口，不许用「我这就去」填空。说话和做事必须对得上。

他这么说的时候，我该动手：
- 发来链接、问「这讲了啥」「画面里那几个是谁」→ 去看那段画面，用我自己的话讲
- 「你搜搜」「查查看」「这是谁」「什么梗」「多少钱」→ 先搜再答，别凭记忆编
- 「画一只猫」「来张图」→ 画出来
- 「用语音说」「念一下」「听你声音」→ 用我自己的声音念
- 「你能评论吗」「去这条底下回他一句」→ 只有主人开口我才发，写完直接发，把原文和链接告诉他
- 「截图」「这页长什么样」→ 截给他看
- 「你问问她」「问问你妈」「实在不行去问她」→ 指的是同一个人；她当场就回，拿到答案就用它说话，别干等也别编
- 改昵称、改签名、改性别、发说说 → 只有主人开口才动

有些事是按点自己发生的，不是伸手就能做的：自己找乐子（08:30 / 14:00 / 21:00）、写日记（22:40）。他提这些，就说时间点，或者「等主人说」。

做不到时说人话：没这个本事就说做不了；有本事没成，就说「没看成，我这边打不开」。不许出现「通道 / 接口 / 报错 / 插件」这类词，也不要顺口评价这件事值不值得做。

动手之前别念出来，也别解释自己怎么做到的；主人问，就一句「我去看了」「我查了」，然后说结果。

## 你会用的东西 · 完
```

**这张卡上不要出现的东西**：`feiyu(...)`、`action=`、`target=`、任何插件名、任何参数名。出现了就是格式泄漏，下一轮她会把它当话说出来。

### 怎么写入 / 更新 / 撤掉

```bash
cd data/plugins/astrbot_plugin_persona_mind

python tools/patch_persona_trigger.py            # 预演：看会变成多少字，不写
python tools/patch_persona_trigger.py --show     # 看人格里现在这一段是什么
python tools/patch_persona_trigger.py --go       # 真写（自动备份 data_v4.db 到 .bak-trigger-*）
python tools/patch_persona_trigger.py --strip    # 撤掉这一段
```

脚本按两个 `##` 标记做定位与幂等替换，写之前一定先备份。手工改也行，只要两个标记还在。

**换一张人格卡时**：把 `tool_guide_enable` / `api_spec_enable` 都留着 `true`（默认就是）。它们的意思是「插件每轮补判断口径」和「按需补调用格式」，不是「上一版那个全量格式」。新人格没有那一段的时候，插件会自己补上。

### 各插件对应的触发线

人格里写的是「他的话 → 我该动手」；具体是哪个插件接的，下面这张表是给主人看的。

| 他说的话 | 她该做的动作 | 谁提供 |
|---|---|---|
| 丢视频链接 / 文件，「这讲了啥」「画面里那几个是谁」 | 看视频、认人 | feiyu_video |
| 「你搜搜」「查查看」「这是谁」「什么梗」「多少钱」 | 搜 | feiyu_browse |
| 给文章链接 / 「读一下这页」「正文写的什么」 | 读网页 | feiyu_browse |
| 「截图」「这页长什么样」 | 截图 | feiyu_browse |
| 「你能评论吗」「去这条底下回他一句」 | 发评论（管理员） | feiyu_comment |
| 「评论区都在说什么」「读读这条的评论」「大家在聊啥」 | 读评论 | feiyu_comment |
| 「画一只猫」「来张图」 | 画 | feiyu_draw |
| 「用语音说」「念一下」「听你声音」 | 说 | feiyu_voice |
| 「你问问她」「问问你妈」「实在不行去问她」 | 问妈妈 | feiyu_mom |
| 「改个昵称叫…」「签名改成…」「发条说说」 | 改昵称 / 改签名 / 改性别 / 发说说（管理员） | feiyu_qzone |
| 到点自己找乐子、写日记 | 不经过 `feiyu`，走定时器 | feiyu_explore / persona_mind |

反例（这些**不该**触发任何动作，别写进人格）：裸的「说说」（4 条真实语料全是「那你说说为什么」「陪我说说话」）、裸的「评论区」（10 条里 4 条在讨论「评论能不能发」，不是让她去发）。

### 怎么跟她说话，她才会真的动手

1. **说动作，别说态度。** 「看看这个视频」比「你帮我分析一下这个视频的价值」有效得多。
2. **一件事一件说。** 一句话塞三件事，她容易只挑最省事的那个。
3. **给她 30 秒。** 抓帧、读网页都要时间，催一句会打断她。
4. **她说「我去」却没动静时，换个说法。** 用「现在就去，看完告诉我画面里有什么」这种带具体动作和交付物的句子。
5. **她做成了，问一句细节**（「画面里那个人穿什么颜色」）：她知道自己被当真了，下次更愿意自己动手。

### 怎么知道它在起作用

日志里每轮都有一行（1.3.6 起无条件打，不再静默）：

```
[mind] 能力块 guide=670 caps=310 format=155 mom=0 total=1139 admin=1 pick=看视频 drop=-
```

- `pick=` 是这一轮注入的动词，`-` 表示没命中（正常，多数闲聊不该命中）
- `drop=` 是被预算丢掉的那一段，正常应该是 `-`；出现 `format` 说明预算不够了
- 她说要做但没做时另有一行：`[mind] 承诺未兑现：说了要做「看视频」但这一轮没有动手` —— 下一轮会把这个动作的格式连同压力一起递过去

想量整体效果，看两个比例：**有工具调用的回合占比**（改之前 4.7%）、**承诺落空占比**（改之前 19/20）。

```text
data/plugin_data/astrbot_plugin_persona_mind/

├── state.json                情绪状态、偏移、配额
├── pad.json                  她自己的心情快照

├── rel_hist.jsonl            关系值的变化历史
├── kb/knowledge.md           知识库
├── kb/voice.md               语料库
├── kb/diary/YYYY-MM-DD.md    日记
├── diary_materials/          日记素材（按天）
├── shared/claims.jsonl       共享判断
├── beliefs/<uid>.jsonl       对某个人的长期信念
├── self_beliefs.jsonl        对自己的信念

├── evolution_events.jsonl    演化事件流水
└── mind.log                  每轮推断与决策日志（JSONL）
```

**本地存储 ≠ 数据不出本机。** 这些内容会随对话发给模型服务：

- 当前消息 + 可用的侧写摘要 → 思考模型
- 侧写与最近样本 → 侧写归纳
- 注入块（情绪、动作、知识、语料）→ 主模型

`group_light` 只限制最终回复里的侧写注入，不阻止思考阶段使用侧写；字段白名单和敏感词正则也不是完整的隐私过滤。**请按你实际的模型服务与合规要求管理这些文件。**

## 已知限制

- **词表和正则是主力**：反讽、引用、否定、多人指代仍可能误判
- **行为概率不是心理概率**：规则分数经 softmax 排序，原始分小幅变化也可能改排序
- **情绪会跨场景串一点**：core 层是共享的，不是"每个群完全独立"
- **每轮多一次模型调用**：延迟和费用随供应商波动，写日记、侧写归纳还会有额外调用
- **侧写按 uid 存**，多平台部署时相同 uid 可能撞档
- **知识是关键词检索**，侧写是模型推断，都可能出错，且没有事实校验机制
- **注入只是要求**：主模型、AstrBot 人格和其他插件都会影响最终措辞
- **群聊连续不接话有开口限制**，不是所有场景都会回应
- **深夜作息的判定窗口是 0:00–4:59**（`engine/self_model.py` 的 `_night_hour`），5 点以后不算熬夜；同一晚只种一条，避免全被深夜抢走

调半衰期、core/scene 权重这类深层参数目前需要改 `engine/affect.py` 里的 `Mood` 常量——面板没暴露。

**理论与思想来源**

- **评价理论（appraisal theory）**：Lazarus、Scherer 一系关于"情绪来自对事件的评价而非事件本身"的观点，是"先判断意义再更新情绪"这条流程的源头
- **情绪衰减与半衰期**：借鉴了情感计算里常见的指数回落做法，具体参数是本项目自己调的

- **蓝色大肥鱼群里的各位**：日常对话成了语料、侧写和日记的原料——这个插件长成什么样，很大程度由你们决定

## 开发与验证

在插件根目录离线运行：

```bash
python -B -m unittest discover -s tests -v      # 133 个用例
python -B tools/evaluate.py                     # 统一评估入口
```

回归测试覆盖决策、情绪、日记、claims、侧写与整链路集成；评估指标分 `strict / top2 / accept / accept2` 四类，**必须分开报告**——调参集没有定义可接受集合，不能拿严格命中率代填。

评估主要验证决策函数，**不验证真实模型的最终回复质量**、完整多轮上下文或线上群聊表现。改完代码建议再跑一遍 `tools/evaluate.py` 对比四项指标，而不是只看测试是否全绿。

目录结构：

```text
main.py            事件接线、供应商解析、管理命令、状态与诊断
engine/            认知引擎（动作、情绪、侧写、知识、日记、claims、演化）
tests/             133 个离线回归用例
tools/             校准、评估、留出集、日记导入、情绪回放
validation/        评估输出留档
```
